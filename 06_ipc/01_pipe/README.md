## 为什么需要进程间通信

父子进程的普通变量独立。管道让一个进程把字节写入内核缓冲，另一个进程通过 read 取得字节。本节方向为父写、子读；下一节再将子程序 stdout 接到管道，供父进程读取。

## pipe 的接口

~~~c
int pipefd[2];
if (pipe(pipefd) == -1) {
    /* errno 表明失败原因 */
}
~~~

pipe 成功返回 0，并把两个描述符写进数组。pipefd[0] 是读端，pipefd[1] 是写端。0/1 在这里是数组下标；实际描述符可能为 3/4，不能和标准输入 0、标准输出 1 混为一谈。

普通匿名管道是单向字节通道，数据保存在内核缓冲，不创建本节目录下的磁盘文件，不使用路径连接。fork 前创建管道，fork 后父子继承引用同一管道的端点。分别在两个不相关进程中调用 pipe 会得到不同管道，整数碰巧相同也不使其连通。

## 为什么双方要先关闭不用的端

~~~text
fork 后：父有读端、写端；子也有读端、写端
关闭后：父只保留写端 → 内核管道缓冲 → 子只保留读端
~~~

父进程关闭 pipefd[0]，子进程关闭 pipefd[1]。这是关闭各自表项，不是把整个管道关闭。父写完后关闭最后保留的写端；子把缓冲数据读完后，read 才返回 0。

如果子忘记关闭自己的写端，即使父已关闭写端，仍存在一个写引用，子读空后也不会得到 EOF。如果父保留写端却先 waitpid，而子在等 EOF，两者会互相等待。关闭不只是清理资源，也在表达通道生命周期。

## 本节阻塞 read 的三种结果

| 条件 | 请求读取非零字节时的结果 |
|---|---|
| 缓冲里有数据 | 返回已读字节数，大于 0 |
| 缓冲为空，仍有写端引用 | 阻塞等待，直到有数据、写端全部关闭，或发生中断/错误 |
| 缓冲为空，写端引用全关闭 | 返回 0，表示 EOF |

所有写端关闭时，缓冲中的已有数据仍可先读出；不是 close 后立即丢数据。判断的是所有进程、所有副本中是否还有写端引用，不是仅看某个进程是否写完或退出。

read 返回 -1 是错误，与 EOF 不同；EINTR 本例重试。非阻塞模式还可能用 EAGAIN 表示暂时无数据，本节没有启用非阻塞。

## 两种运行模式

- normal：父写入 16 字节 ABCDEFGHIJKLMNOP，关闭写端，然后回收；子用 6 字节数组循环 read，累计接收 16 字节，读到 EOF 后关闭读端并退出 0。
- hold：父写完后仍保留写端，等待终端回车；子会读到全部 16 字节，但读空后等待，暂不出现 EOF。按回车后父关闭写端，子随即得到 EOF 并退出，父完成回收。

hold 使用 getchar 控制关闭时机，在 COM12 前台运行，不加 &。不要提前按回车，也不要把输入重定向为已结束的文件；否则观察窗口会直接结束。子每次打印读取结果后 fflush，避免 C 库缓冲把已读数据的观察延迟到退出时。

读取的精确分块不是协议：普通管道没有消息边界，发送一次不等于接收一次。本例常见返回 6、6、4、0，但不依赖固定分块。应检查按顺序拼接得到完整 16 字节，以及最终返回 0。子进程输出字节用 %.*s 限定打印长度，本节负载为无内嵌 NUL 的 ASCII 文本。

父使用之前熟悉的 write_all 处理返回长度和 EINTR。写入的 16 字节不包含 C 字符串结束符，子缓冲也不需要附加 NUL 才能完成本节传输。

## COM12：保留写端的对照

~~~sh
./pipe_demo hold
~~~

先不按回车，观察子累计 total=16 后没有 EOF、程序尚未结束。然后按一次回车，应看到父关闭写端，子 read returned 0，父回收。程序结束后紧接检查：

~~~sh
echo $?
~~~

预期为 0。子暂时没有输出不是僵尸：此时它尚未退出，通常阻塞在 read；僵尸是已经退出、待回收。这与前面进程生命周期实验相联系。

## 边界与后续

管道不可 lseek，不能像普通文件那样回退重读；字节被读走后不会作为本管道的历史内容继续保留。管道容量有限，写满时阻塞写可能等待读者消耗，不能把容量固定写成某个数字。

若所有读端引用都关闭，再 write 会产生 SIGPIPE，默认终止写入进程；忽略或适当处理后可以看到 write 失败及 EPIPE。它与没有写端时 read 的 EOF 是相反方向的规则。本节不故意触发该路径，后续结合错误处理实验学习。

PIPE_BUF 的短写入原子性用于避免多写者的短数据相互穿插，不等于读者每次 read 必须得到一整条消息。需要消息协议时，应用层还要定义长度、分隔符等规则。

本节创建两个相关进程但没有 exec，也没有用 dup2 把标准输出接到管道。先明确端点、关闭、阻塞、字节流、EOF，再组合外部程序输出捕获。
