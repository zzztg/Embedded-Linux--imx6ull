# sigpipe_demo.c 代码阅读课

学习者指出新变量、类型、函数过于集中，因此暂停实验推进。本文解释现有源码，不修改源码或要求重新编译。分段理解之后再做三种模式对照。

## 先认清代码做的三件事

1. 选择收到 SIGPIPE 后的动作：默认、忽略或调用处理函数。
2. 创建管道并关闭唯一的读端，固定“没有读者”的条件。
3. 写一个字节，观察是被信号终止，还是取得 -1/EPIPE 后自行退出。

sigaction 配置动作；sigprocmask 配置递送是否被屏蔽；pipe/close/write 制造本节事件。配置动作和解除屏蔽是两套机制。

## 自己起的变量名与系统接口名

| 名称 | 是什么 | 本例用途 |
|---|---|---|
| action | 我们定义的局部结构体变量 | 保存待安装的信号动作配置 |
| struct sigaction | 系统头文件提供的结构体类型 | 规定配置有哪些成员 |
| sigaction(...) | 函数 | 把配置安装到指定信号 |
| signals | 我们定义的局部变量 | 保存一个信号集合 |
| sigset_t | 系统头文件提供的类型 | 表示信号集合，不必自行按整数位实现 |
| pipefd | 我们定义的两个整数的数组 | 保存管道读写端编号 |
| count | 我们定义的局部变量 | 保存 write 返回值 |
| ssize_t | 有符号整数类型 | 能保存字节数与 -1 |
| error | 我们定义的局部变量 | 在失败后保存 errno 的数值副本 |
| caught_signal | 文件作用域的静态变量 | 处理函数写入、主流程读取的简单标志 |
| signum | 处理函数的参数 | 这次递送的信号编号 |

类型、变量、函数要分开看。action 可以改名为 config；它不是系统保留名称。struct sigaction 与 sigaction() 名称相同，但前者是类型，后者是函数。

## 一：头文件与编译接口

_POSIX_C_SOURCE 200809L 是头文件接口选择宏，放在 include 前，使严格 C 模式下可见本例需要的 POSIX 声明。它在编译阶段起作用，不是运行时切换 Linux 的模式。L 是整数常量后缀。

signal.h 提供信号类型、动作常量和相关声明；errno.h 提供 errno、EPIPE 等；string.h 提供 strcmp、strerror；unistd.h 提供 pipe、close、write 及 ssize_t；stdio.h 提供输出与刷新接口。

## 二：处理函数和跨调用标志

~~~c
static volatile sig_atomic_t caught_signal = 0;

static void handle_sigpipe(int signum)
{
    caught_signal = signum;
}
~~~

caught_signal 在函数外定义，静态存储期持续整个程序运行；static 同时限制其链接范围。signum 是本次处理函数调用的参数，返回后生命周期结束，但 caught_signal 不会随之消失。

sig_atomic_t 用于信号处理与普通执行流之间的简单标志访问；volatile 限制相关访问优化。这里仅做一次简单赋值，不据此保证 ++、多个字段组合操作或线程同步。

处理函数只记录编号，主流程稍后打印。这样避免在异步处理上下文里调用 printf、perror 等不适合的接口。

## 三：检查命令行

运行 ./sigpipe_demo ignore 时，argc=2，argv[0] 是程序名称字符串，argv[1] 是 ignore。strcmp(a,b)==0 表示字符串相等；不是“调用成功”。

条件首先检查 argc，利用 || 短路，参数不足时不继续访问 argv[1]。后面的三个不等判断用 &&，表示该字符串三种有效模式都不匹配。参数错误打印用法并返回 2。

## 四：准备动作配置

~~~c
struct sigaction action = {0};
sigemptyset(&action.sa_mask);
~~~

第一行定义 action，并将成员作零值初始化；不是调用函数。后续仍用规定的接口 sigemptyset 初始化其中的信号集合。

sa_mask 是这个结构体的成员，表示处理函数执行期间要额外屏蔽的信号集合。&action.sa_mask 取得该成员地址，让函数修改它；sigemptyset 把集合初始化为空，表示不额外指定其他信号。此操作本身不修改当前线程的屏蔽字，也不是清除待处理信号。通常当前正在处理的那一种信号仍自动暂时屏蔽，本例没有设置改变这一行为的标志。

sa_flags 在本例保持 0，未选用额外行为。此阶段只要知道 action 是配置对象，成员各自描述配置的一个部分。

## 五：选择动作

~~~c
action.sa_handler = SIG_DFL;
action.sa_handler = SIG_IGN;
action.sa_handler = handle_sigpipe;
~~~

这是三种可选赋值，不是顺序全部执行；源码通过 if/else 选择一条。

SIG_DFL 与 SIG_IGN 是系统提供的特殊动作值，分别表示使用默认动作、忽略信号；它们不是本例自己编写的函数。函数名 handle_sigpipe 在赋值位置提供处理函数地址，没有括号，所以不是此时立即执行处理函数。

对于 SIGPIPE，默认动作是终止；其他信号的默认动作不一定相同。因此 SIG_DFL 不能直接理解成所有信号一律结束进程。

## 六：安装配置

~~~c
sigaction(SIGPIPE, &action, NULL);
~~~

| 参数 | 本例含义 |
|---|---|
| SIGPIPE | 配置哪一种信号 |
| &action | 提供新配置的地址 |
| NULL | 不要求函数把旧配置写回给我们 |

前面填写 action 是准备数据，这里调用函数才使配置生效。成功返回 0，失败返回 -1 并设置 errno。内核读取并记录配置；不要求主流程持续保存这一局部结构体的地址作为信号配置对象。

## 七：信号集合与解除屏蔽

~~~c
sigset_t signals;
sigemptyset(&signals);
sigaddset(&signals, SIGPIPE);
sigprocmask(SIG_UNBLOCK, &signals, NULL);
~~~

逐步解释：定义一个名为 signals 的集合变量；初始化为空集合；把 SIGPIPE 加入，成为只含这一种信号的集合；将集合中的信号从当前线程的屏蔽字中移除。本例为单线程，使用 sigprocmask。

SIG_UNBLOCK 是选择操作方式的常量；NULL 表示不保存旧屏蔽字。这个调用不会把其他信号的屏蔽状态全部清空。如果 SIGPIPE 本来就没被屏蔽，这一步允许执行但不改变它。

这一块用于固定实验环境，避免继承来的屏蔽状态影响 default 模式。源码把三个调用用 || 连起来，遇第一个失败就进入错误处理；阅读时先拆成上面的顺序更容易理解。此处示意省略了源码中的返回值检查。

| 两个集合 | 各自用途 |
|---|---|
| action.sa_mask | 处理函数执行期间额外屏蔽哪些信号，由 sigaction 安装 |
| signals | 本次要解除屏蔽的信号列表，交给 sigprocmask 使用 |

忽略意味着收到信号时采用忽略动作；屏蔽意味着暂缓递送，它们不是同一设置。本块应单独讲解，不能只给出“保证不屏蔽”的结论让学习者猜。

## 八：建立无读者条件

pipe(pipefd) 返回两端编号；close(pipefd[0]) 关闭唯一读端；本节没有 fork 或 dup，所以不会有其他读端引用。保留 pipefd[1]，稍后向它写入。关闭的只是内核表项，不是把数组元素自动改成 -1。

写入前先打印模式并 fflush(stdout)，让消息在可能的信号终止前提交。fflush 失败返回 EOF 宏；这是该函数自己的失败约定，与 read 返回 0 表示管道 EOF 是不同接口的规则。

## 九：写入并保存结果

const char byte='X' 定义一个单字节变量；&byte 是地址，write 的第三个参数 1 表示只发送一个字节。sizeof 字符串等概念不参与这次单字节实验。

do/while 只在 -1 且 errno=EINTR 时重试。EPIPE 不满足该重试条件，不能一直重试无接收者的管道。

~~~c
int error = count == -1 ? errno : 0;
~~~

等价于：

~~~c
int error;
if (count == -1) {
    error = errno;
} else {
    error = 0;
}
~~~

这是保存错误编号的局部副本，不是定义一个新的 errno，也不是在成功时清空运行库的 errno。先保存，是为了随后日志调用不影响本次错误的判断。

## 十：三种模式的后续路径

default 在本例未屏蔽的 SIGPIPE 默认动作下终止，不到达 after write；ignore 与 catch 能继续执行主流程并处理 -1/EPIPE。strerror(error) 把保存的错误编号转换为说明字符串，并不改变写入结果。

catch 模式可看到 caught_signal 被处理函数设置；ignore 没有调用这个函数，标志保持 0。本例识别 EPIPE 后关闭写端并 return 1，主动向 Shell 报告发送失败。

%zd 用于有符号的 ssize_t；%d 打印 int；(int)caught_signal 是用于格式匹配的类型转换。信号编号、errno 编号、函数返回值、程序退出码是不同类别，不应混为一谈。

## 推荐讲解顺序

先讲 action 类型/变量、sa_handler、sigaction 三步；随后讲集合、屏蔽与动作的区别；再复习处理函数的存储期和安全访问；最后读写入及错误分支。每个新接口先讲参数、返回值和调用产生的效果，再运行实验。当前不要求一次记住整个程序。
