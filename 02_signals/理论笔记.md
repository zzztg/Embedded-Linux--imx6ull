# 进程与信号：入门理论

## 程序、进程与 Shell

程序是保存的可执行文件；进程是程序启动后的运行实例。每个实例有自己的执行状态、地址空间和 PID。本实验两次启动同一程序，各有自己的 `stop_signal`。共享内存等显式共享机制本轮不设专章，实际项目需要时再学。

Bash 是解释命令的 Shell，本身也是一个进程。它启动应用，操作系统调度应用执行。应用的 `main` 返回时该运行实例结束，系统和其他应用继续运行。

## 前台、后台和退出状态

- `./signal_demo`：前台运行，Shell 等待它结束。
- `./signal_demo &`：后台启动，Shell 可以继续接收命令。
- `$!`：最近启动的后台任务对应的 PID；`[1]` 是当前 Shell 的任务号。
- `jobs`：当前 Shell 的作业；`ps`：进程信息。
- `wait "$study_pid"`：等待该子进程并取得退出状态。
- `$?`：上一条命令的退出状态，应紧接目标命令读取。

`main` 返回 0 表示本程序约定的成功结果。`sleep` 因 SIGTERM 终止时，Bash 将状态表示为 143，即 128 + 15。我们捕获 SIGTERM 后走完 `main` 的正常退出流程，所以状态为 0。

## 信号的来源和处理方式

信号是对进程或线程的通知。来源包括终端操作、其他进程发出的请求和内核检测到的事件。

本板实验中，默认 `kill PID` 发送 SIGTERM（15）；Ctrl+C 在通常的终端设置下向前台进程组发送 SIGINT（2）。`kill` 可以指定其他信号，不与 SIGTERM 固定绑定。

进程可使用默认动作、忽略信号或登记处理函数。不同信号的默认动作可能是终止、暂停、继续或忽略。SIGKILL、SIGSTOP 无法被捕获、忽略或屏蔽。

普通信号在同一种信号已待处理时再次到来，可能合并，不保证逐次计数。因此普通信号不适合作为必须准确计数的数据队列。实时信号与 IPC 后续学习。

## 注册和触发是两个时机

```c
struct sigaction action = {0};
action.sa_handler = handle_stop;
sigemptyset(&action.sa_mask);
sigaction(SIGINT, &action, NULL);
sigaction(SIGTERM, &action, NULL);
```

- `{0}` 初始化结构体，使本例的 `sa_flags` 为 0。
- `sa_handler` 保存函数指针，填写配置时不执行回调。
- `sigaction(signum, &action, NULL)` 为当前进程的指定信号登记配置。
- 第三个参数可用于取得原来的配置；本例传 NULL，表示不取回它。
- 调用返回 0 表示成功，返回 -1 表示失败，失败原因由 `errno` 提供。
- 实际源码在 `if` 中检查失败；`||` 是短路或，前一项失败后后面的调用不会执行。

## 信号如何进入回调

信号交付时，内核保存被打断的执行上下文，安排进程在用户态执行处理函数。它没有为本例创建新线程。回调正常返回后，恢复被打断的流程。

```text
收到信号 → handle_stop(signo) → 写入 stop_signal → 回调返回
→ 主循环再次检查标志 → 跳出循环 → 打印 → main 返回 0
```

回调返回与进程退出是不同事件。Linux 信号处理函数运行在用户进程中；单片机硬件中断的类比可帮助理解异步通知，但两者不是同一机制。

## 信号屏蔽的范围

屏蔽表示暂缓交付，信号可以处于待处理状态。忽略是另一种处理方式。

`action.sa_mask` 指定回调执行期间要额外屏蔽的信号。`sigemptyset` 建立空集合；本例没有额外指定信号。默认情况下，本次正在处理的那个信号也会临时被屏蔽，回调返回后恢复原来的屏蔽状态。

这个配置不会自动覆盖 `main` 的整段循环。因此，前面问题的答案是：尚未进入回调时，SIGINT 不会仅因为 `sa_mask` 的配置而被屏蔽。主动保护主流程中的区段，需要另外管理当前信号屏蔽字；单线程程序可使用 `sigprocmask`。

## 原子标志与处理函数的限制

```c
static volatile sig_atomic_t stop_signal = 0;
```

- 文件作用域的 `static` 限制该变量在当前 C 文件内可见；各个进程仍各有自己的变量。
- `volatile` 约束编译器对变量访问的优化。
- `sig_atomic_t` 是整数类型，保证信号场景下单次读取或赋值完整。

它不会自动关闭硬件中断。`stop_signal++` 等多步操作不会仅因为使用这个类型而获得整体原子性。

处理函数只修改标志。`printf` 使用内部缓冲状态，不属于异步信号安全函数；若在主流程调用尚未完成时被信号打断，再从回调调用它，可能操作到不一致的内部状态。打印、整理状态和复杂清理放在主流程。

## 源码中剩余细节

- `_POSIX_C_SOURCE 200809L` 在包含头文件前定义，用于声明所需的 POSIX 接口。
- `getpid()` 返回当前进程的 PID；本例转为 `long` 后用 `%ld` 打印。
- `fflush(stdout)` 把 C 库标准输出缓冲中的内容送出，便于看到准备完成的提示。
- `sleep(1)` 让当前线程休眠，其他进程继续运行。信号可能使休眠提前结束；主流程随后再检查标志。
- 处理函数只设标志，并不保证所有业务数据都已经保存；真正的资源清理须由程序明确编写。
