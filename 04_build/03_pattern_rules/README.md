# 实验 04-03：自动变量、模式规则与构建预览

三个 C 源码沿用上一节，使用独立的小节目录。学习者亲手编译。基础变量仍为 CC、CFLAGS、LDFLAGS、TARGET、OBJECTS。

## 三个自动变量

这些变量在执行某条规则的配方时，表示这条规则的上下文；由 make 展开后再把命令交给 Shell。

| 自动变量 | 意义 | 本节例子 |
|---|---|---|
| $@ | 当前目标名 | 编译时为 main.o，链接时为 file_app |
| $< | 第一个依赖文件 | 编译 main.o 时为 main.c |
| $^ | 所有普通依赖文件的列表，重复项去重 | 链接时为 main.o io_utils.o |

本节链接规则：

```make
$(TARGET): $(OBJECTS)
	$(CC) $(CFLAGS) $(LDFLAGS) $^ -o $@
```

链接需要两个 .o，因此使用 $^。编译规则使用 $<，只把对应 .c 作为编译输入；头文件作为依赖项影响更新时间判断，并通过源码中的 #include 展开。

## 模式规则

```make
%.o: %.c io_utils.h
	$(CC) $(CFLAGS) -c $< -o $@
```

% 是 make 的模式匹配标记。在生成 main.o 时匹配 main，%.c 对应 main.c；生成 io_utils.o 时匹配 io_utils，%.c 对应 io_utils.c。

对于 main.o，这条规则等价于 main.o 依赖 main.c 和 io_utils.h，执行编译 main.c、输出 main.o。两个模块共同包含 io_utils.h，因此本节保留这个公共头文件依赖。

OBJECTS 仍决定默认程序需要哪些目标文件；模式规则提供需要某个 .o 时如何生成它的方法，不自动把目录内每个 .c 都加入程序。

后续模块有不同头文件时，将学习 -MMD/-MP 和 .d 依赖文件，让编译器报告实际包含关系，减少手工维护。

## WSL：先看计划，再亲手执行

```sh
cd /mnt/c/Users/dingf/Desktop/imx6ull/04_build/03_pattern_rules
make -n
make
echo $?
file file_app
```

新目录第一次 make -n 预计打印三条构建命令；在本节这份 Makefile 中只打印普通配方，不执行编译。随后 make 仍需实际执行两次编译和一次链接。状态应为 0，产物应为 ARM 静态可执行程序。

## WSL：某个模块需要更新时，预览不会替你完成构建

```sh
sleep 1
touch io_utils.c
make -n
make
```

预览应打印 io_utils.c 的编译和最终链接；实际 make 仍执行这两条，因为预览没有更新 .o 和程序。重点把自动变量的展开值与规则中的目标、依赖对上。

## 选项与边界

- -n 是构建预览。本节没有递归 make 或其他特殊配方，因此可以直接观察打印而不执行的效果；包含递归 make 等特殊情况的工程需要另外理解其行为。
- 上一节命令行的 CFLAGS 赋值没有修改 Makefile 文件。新小节的默认编译选项由这里的 CFLAGS 决定。
- 本节只改变构建表达方式，文件写入行为仍是已上板验证的程序。
- 自动变量、模式规则与增量构建结合后，依赖关系仍是正确重建的基础。
