# 文件 I/O：理论与代码阅读

## 从单片机经验连接到 Linux

单片机应用经常通过外设库或寄存器访问硬件。Linux 应用在用户态运行，通过系统调用请求内核完成文件或设备操作。

应用调用的 `open/read/write/close` 接口通常经由 C 库封装进入内核。内核检查参数和权限，管理已打开文件，再通过文件系统或设备驱动完成相应工作。

普通文件通常由文件系统管理；`/dev` 下的设备节点由对应驱动提供操作。统一的接口便于应用开发，具体读写含义由文件或设备类型决定。

## 路径、文件与描述符

- 路径用于找到文件，如 `/root/linux-study/03_file_io/02_write/note.txt`。
- 相对路径从进程的当前工作目录解析。写入实验先 `cd /root/linux-study/03_file_io/02_write`，所以 `note.txt` 位于该目录。
- 读取实验在相邻的 `03_read` 目录运行，输入路径使用 `../02_write/note.txt`；`..` 表示上一级目录。各节的相对路径不能脱离当前工作目录解释。
- `open` 成功后返回文件描述符 fd，即进程的描述符表中的非负整数索引。
- `write/read/close` 用 fd 引用已打开的文件。
- 不同进程的 fd=3 可以引用不同的文件。fd 与 PID 属于不同的编号体系。
- 关闭后该数字可被后续打开操作复用，不能继续当作原来的文件使用。

正常终端应用通常继承 0、1、2，分别对应标准输入、标准输出和标准错误。`open` 选择当前最低的可用描述符，因此第一次新开文件常返回 3，但代码应使用实际返回值。

## 观察当前终端的描述符

先在 COM12 中逐条执行：

```sh
echo $$
ls -l /proc/$$/fd
```

`$$` 是当前 Shell 的 PID。`/proc/PID/fd` 是内核提供的运行时视图，其中的链接展示该进程打开的描述符及其目标。

观察编号 0、1、2 指向哪里。在串口登录中，它们通常都连接到串口终端：0 用于输入，1 用于正常输出，2 用于错误输出。若看到 255 等其他编号，那是 Shell 自己使用的描述符，可以先记录。

## 打开方式与创建权限

本例：

```c
fd = open(argv[1], O_WRONLY | O_CREAT | O_TRUNC, 0644);
```

| 参数或标志 | 含义 |
|---|---|
| `argv[1]` | 命令行提供的目标路径 |
| `O_WRONLY` | 只写方式 |
| `O_RDONLY` | 只读方式 |
| `O_RDWR` | 读写方式 |
| `O_CREAT` | 不存在时创建普通文件，不自动创建父目录 |
| `O_TRUNC` | 本例以写方式打开已有普通文件时清空其内容 |
| `O_APPEND` | 每次写入定位到文件末尾，后续做追加实验 |
| `0644` | 创建时请求的权限，用八进制表示 |

`0644` 表示所有者读写，所属组和其他用户只读。新文件的实际权限还受 `umask` 等因素影响；在没有默认 ACL 的通常情形下为 `mode & ~umask`。已有文件的权限不会因为这次 mode 参数自动变为 0644。

权限的 4、2、1 分别代表读、写、执行。对普通文件，读写权限控制数据访问；运行可执行文件还需要执行权限。

## 读写与文件偏移

| 接口 | 成功时的返回值 | 需要理解的边界 |
|---|---|---|
| `open` | 非负 fd，0 也可以是成功结果 | 失败返回 -1 |
| `write` | 实际写入字节数 | 可能少于请求长度，失败返回 -1 |
| `read` | 实际读到字节数 | 普通文件返回 0 表示到达文件末尾；失败返回 -1 |
| `close` | 0 | 释放描述符，失败返回 -1 |

普通文件打开时偏移通常从开头开始，成功读写会向后推进偏移。`lseek` 可改变可定位文件的偏移，后续实验展开。

定位和覆盖写入的完整说明、源码入口、编译和上板步骤见：[文件位置实验](文件位置实验.md)。学习者已确认掌握前面的读取与 EOF 内容，继续本节；空文件补充实验不作为推进的必需步骤。

文件 I/O 处理字节。读到的字节不会自动附加 C 字符串结束符 `\0`；写入长度也由调用者指定。本例写入换行，不写入字符串末尾的 `\0`，所以共 27 字节。

### 读取、有效长度与 EOF

`read(fd, buffer, sizeof(buffer))` 请求最多读取缓冲区容量那么多字节。返回正数时，只有缓冲区前面该数量的字节是本次读到的数据，剩余空间可能保留旧内容。短读不是错误，也不能单凭短读断言下一次一定返回 0。

对本例 27 字节普通文件和 16 字节缓冲区，典型过程是读 16 字节，偏移从 0 到 16；再读 11 字节，偏移到 27；再调用一次返回 0。读取位置是在内核中保存的打开文件状态，重复调用不会自动回到开头。重新独立 `open` 这个普通文件则从头开始；共享打开文件状态的情况在后续进程章节展开。

本例每次请求读取的长度均大于 0，所以返回 0 表示当前位置已到普通文件末尾。EOF 是接口返回的状态，没有一个必需的“文件结束字符”；数据中的 `\0` 不代表 EOF。请求长度为 0 也可返回 0，因此不能脱离参数和资源类型解释返回值。

如果希望将读到的文本当成 C 字符串使用，需要额外预留一个字节并在有效内容末尾添加 `\0`。读取示例采用原始字节输出：`write_all(STDOUT_FILENO, buffer, (size_t)count)`，不依赖字符串结束符。

## 错误处理和信号的联系

系统接口失败时，返回值提示失败，`errno` 提供原因，`perror` 打印原因。仅在接口报告失败时解释 errno，避免使用之前留下的错误值。

常见错误包括：父目录或文件不存在、权限不足、文件系统只读、存储空间不足。诊断先看返回值和具体错误，再检查路径、身份、权限与挂载状态。

有些阻塞操作被信号打断时会返回 -1，并设置 `errno=EINTR`。部分接口在特定条件下可自动重启，不能假定所有操作都如此。

写入也可能只完成一部分。本例的 `write_all` 根据返回字节数推进指针、减少剩余长度；遇到 EINTR 重试。即使这次小文件一遍就写完，也应理解返回值表达的是实际完成数量。

## C 库缓冲与数据保存

`printf/fopen/fwrite` 属于标准 C 的 stdio 接口，可能维护 C 库缓冲；`write` 使用文件描述符，接口层次不同。后续用实验观察两层接口。

具体缓冲策略、fflush 的边界、源码与亲手编译步骤见：[缓冲实验](缓冲实验.md)。该实验通过后台程序与重定向，在程序存活期间和正常返回后观察文件大小，复用已学习的进程、描述符和 wait。

`write` 返回成功通常表示数据已被内核接受，不等同于数据已经写到存储介质。`close` 释放描述符，也不提供掉电保存保证。需要同步文件数据时使用 `fsync` 或相关接口，并检查结果；创建文件时目录项的持久化等细节将在文件系统章节学习。

## 阅读本例的顺序

运行 `./file_write note.txt` 时，argc 为 2，argv[0] 是程序名参数，argv[1] 是 `note.txt`。

1. 检查参数数量，错误时打印用法并返回 2。
2. 使用路径和标志打开或创建文件，失败时打印原因并返回 1。
3. 打印 fd，循环写入全部数据。
4. 关闭 fd，检查结果。
5. 打印写入长度并返回 0。

`echo $?` 紧接程序执行，查看这个程序的结果；`cat note.txt` 从另一个进程读取文件；`ls -l` 检查大小和权限。

本章先做创建与写入，再做读取、追加、偏移和失败路径实验。最后连接到设备节点和驱动接口。
