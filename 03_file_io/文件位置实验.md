# 文件位置：lseek、重新读取与覆盖写入

源码：[file_seek.c](04_seek/file_seek.c)。这仍属于文件 I/O 章节。读写返回值、有效长度和 EOF 已完成讲解，继续学习普通文件的读写位置。操作路径已按 2026-10-12 整理后的目录更新。

## 理论

`off_t lseek(int fd, off_t offset, int whence)` 成功时返回相对于文件开头的新位置，单位为字节；失败返回 `(off_t)-1` 并设置 errno。off_t 用于表示文件偏移，不应把它当作实际读写的字节数。

| whence | 新位置 |
|---|---|
| SEEK_SET | 文件开头 + offset |
| SEEK_CUR | 当前读写位置 + offset |
| SEEK_END | 文件大小 + offset |

`lseek(fd, 0, SEEK_CUR)` 查询当前位置；`lseek(fd, 0, SEEK_SET)` 回到开头。负 offset 可以向前移动，例如 `lseek(fd, -2, SEEK_CUR)`；结果不能是负位置。

同一次以 O_RDWR 打开的普通文件，read 和 write 使用同一个位置。lseek 改变这个内核状态；它不会修改用户态 buffer 指针，也不会自行读写文件内容或改变文件大小。

未使用 O_APPEND 时，普通文件的 write 从当前位置写入。写入已有范围时覆盖原字节，不把后面的内容整体向后移动。写过原来的末尾会扩展文件。O_APPEND 会在每次 write 时定位到当时的末尾，不能通过 lseek 把这种写入改成中间覆盖。

普通文件支持定位；管道、socket 和 Linux 终端不支持这样的定位，会报 ESPIPE。统一的 read/write 接口不意味着所有资源都支持全部文件操作。

read_preview 为缓冲区分配 5 字节，每次最多读 4 字节，再执行 `buffer[count] = '\0'`。因此本例可以用 `%s` 显示文本。原始二进制内容仍应按实际长度处理，包含零字节的内容不能用 `%s` 完整显示。

run_demo 的 `||` 从左到右执行，只要某一步报告失败就跳过后续步骤。main 在 run_demo 返回后关闭描述符。

## 对比实验：O_APPEND

源码：[file_append.c](05_append/file_append.c)。与 file_seek.c 的行为差异来自打开标志增加 O_APPEND；日志标签 after overwrite 改为 after write。

```c
int fd = open(argv[1], O_RDWR | O_APPEND);
```

O_RDWR 允许读写，O_APPEND 指定每次 write 从当时的文件末尾写入。它不让 read 自动从末尾读，也不让 lseek 失效；lseek 可以把位置设为 2，但接着 write 会定位到末尾再写入。

用独立的 append_demo.txt 准备 ABCDEFGHIJ 加换行，共 11 字节。预期仍可先读取 ABCD 并定位到 2；写入 xy 后偏移变为 13，回到开头后再次读到 ABCD。最终字节为 `ABCDEFGHIJ\nxy`，大小 13 字节。xy 后没有换行，所以 cat 输出后终端提示符可能紧跟在 xy 后面。

```sh

```

追加不等同于打开后手动 lseek 一次到末尾：在支持相应语义的文件系统上，O_APPEND 将每次定位到末尾与该次 write 作为一个原子操作，避免其他写入者在两个独立调用之间改变文件末尾。这个保证针对每次 write，不能扩展为多个 write 组成的整条记录不可交错。NFS 等环境有额外限制，后续并发和文件系统章节展开。

追加示例开发板已验证：初始位置 0；读取 ABCD 后位置 4；lseek 到 2 后 write xy，位置变为 13；SEEK_END 返回 13；回到开头仍读到 ABCD。程序退出状态为 0；cat 显示原始一行 ABCDEFGHIJ，随后 xy，xy 后的提示符紧接输出。学习者未提供 ls -l 的结果，因此不另行声称通过 ls 核对了大小。
